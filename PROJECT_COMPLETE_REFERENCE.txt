================================================================================
1. PROJECT OVERVIEW
================================================================================

CLA is a production-grade, full-stack Corporate Lending Automation platform
that automates the entire corporate loan underwriting process — from document
intake and OCR extraction through financial analysis, rule evaluation, ML risk
scoring, and credit report generation.

The platform supports THREE user portals:
  - COMPANY PORTAL: Companies register, create loan applications, upload
    annual reports (PDFs up to 100 MB). The system auto-detects Balance Sheet,
    P&L, and Cash Flow sections from the annual report.
  - BANK PORTAL: Bank officers/analysts manage applications, review pipeline
    stages, view credit reports, and make final decisions.
  - ADMIN PORTAL: System administrators manage users, companies, rules, and
    view platform-wide analytics.

7. DATABASE SCHEMA (PostgreSQL)
================================================================================

All tables have: id (UUID PK), created_at, updated_at (auto-managed)

TABLE: users
  - email (VARCHAR 255, unique, indexed)
  - full_name (VARCHAR 255)
  - hashed_password (VARCHAR 255)
  - role (ENUM: admin, officer, analyst, viewer, company)
  - status (ENUM: active, inactive, suspended)
  - department (VARCHAR 100, nullable)
  - phone (VARCHAR 20, nullable)
  - is_verified (BOOLEAN)
  - last_login (VARCHAR 50, nullable)
  - profile_notes (TEXT, nullable)
  - company_id (FK → companies.id, nullable) — links company users to their company

TABLE: companies
  - name (VARCHAR 255, indexed)
  - registration_number (VARCHAR 100, unique)
  - tax_id (VARCHAR 50, nullable)
  - gst_number (VARCHAR 50, nullable)
  - company_type (ENUM: private_limited, public_limited, partnership, sole_proprietorship, llp, other)
  - industry (ENUM: manufacturing, retail, wholesale, services, technology, healthcare, construction, real_estate, agriculture, financial, hospitality, transportation, energy, other)
  - status (ENUM: active, under_review, suspended, closed)
  - incorporation_date (VARCHAR 20, nullable)
  - country_of_incorporation (VARCHAR 100, default "India")
  - registered_address (TEXT, nullable)
  - city, state, postal_code
  - contact_email, contact_phone, website
  - annual_turnover (NUMERIC 18,2, nullable)
  - number_of_employees (INTEGER, nullable)
  - notes (TEXT, nullable)

TABLE: loan_applications
  - application_number (VARCHAR 50, unique, indexed)
  - company_id (FK → companies.id, CASCADE)
  - assigned_officer_id (FK → users.id, SET NULL, nullable)
  - loan_amount_requested (NUMERIC 18,2)
  - loan_purpose (ENUM: working_capital, capital_expenditure, debt_refinancing, expansion, acquisition, trade_finance, other)
  - loan_tenure_months (INTEGER)
  - interest_rate_requested (NUMERIC 6,4, nullable)
  - collateral_description (TEXT, nullable)
  - collateral_value (NUMERIC 18,2, nullable)
  - status (ENUM: draft, submitted, under_review, ocr_processing, ocr_complete, ratio_calculated, rule_evaluated, ml_predicted, report_generated, approved, rejected, manual_review, withdrawn)
  - ocr_completed, ratios_calculated, rules_evaluated, ml_predicted, report_generated (BOOLEAN pipeline flags)
  - final_decision (ENUM: approved, rejected, manual_review, pending)
  - decision_reason (TEXT, nullable)
  - officer_notes (TEXT, nullable)
  - risk_score (NUMERIC 5,2, nullable)

TABLE: documents
  - application_id (FK → loan_applications.id, CASCADE)
  - document_type (ENUM: balance_sheet, profit_loss, cash_flow, annual_report, auditor_report, gst_report, bank_statement, other)
  - status (ENUM: uploaded, processing, extracted, failed)
  - original_filename, stored_filename, file_path, file_size_bytes, mime_type
  - checksum_sha256 (nullable)
  - financial_year (VARCHAR 20, nullable)
  - processing_error (TEXT, nullable)
  - parent_document_id (FK → documents.id, self-referencing, SET NULL, nullable) — for annual report sub-documents
  - page_range_start, page_range_end (INTEGER, nullable) — page boundaries for extracted sections
  - ocr_processed (BOOLEAN)

TABLE: ocr_data
  - document_id (FK → documents.id, CASCADE, unique)
  - raw_text (TEXT, nullable)
  - confidence_score (FLOAT, nullable)
  - page_count (INTEGER, nullable)
  - extracted_fields (JSONB, nullable) — parsed financial fields
  - extraction_metadata (JSONB, nullable)

TABLE: financial_ratios
  - application_id (FK → loan_applications.id, CASCADE, unique)
  - financial_year (VARCHAR 20, nullable)
  - extracted_financials (JSONB, nullable) — raw financial data used
  - ratios (JSONB, nullable) — computed ratio values
  - overall_health (VARCHAR 50, nullable) — e.g., "healthy", "warning", "critical"
  - health_notes (TEXT, nullable)
  - calculation_metadata (JSONB, nullable)

TABLE: predictions
  - application_id (FK → loan_applications.id, CASCADE)
  - model_used (ENUM: logistic_regression, random_forest, xgboost)
  - model_version (VARCHAR 50, nullable)
  - probability_of_default (NUMERIC)
  - outcome (ENUM: approved, rejected, manual_review, error)
  - risk_score (NUMERIC 5,2)
  - risk_level (ENUM: low, medium, high, critical)
  - shap_values (JSONB, nullable) — per-feature SHAP explanations
  - feature_importance (JSONB, nullable)
  - explanation_text (TEXT, nullable)
  - input_features (JSONB, nullable)
  - model_metrics (JSONB, nullable)
  - recommendation (TEXT, nullable)
  - ml_executed (BOOLEAN)
  - skip_reason (TEXT, nullable)

TABLE: credit_reports
  - application_id (FK → loan_applications.id, CASCADE)
  - status (ENUM: generating, completed, failed)
  - filename (VARCHAR 255, unique)
  - file_path (VARCHAR 500)
  - file_size_bytes (BIGINT, nullable)
  - version (INTEGER, default 1)
  - generated_by (VARCHAR 255, nullable)
  - generation_error (TEXT, nullable)

TABLE: rules
  - name (VARCHAR 200, unique)
  - description (TEXT, nullable)
  - category (ENUM: liquidity, profitability, leverage, efficiency, coverage, size, custom)
  - metric_field (VARCHAR 100) — e.g., "current_ratio", "debt_to_equity"
  - operator (ENUM: gt, gte, lt, lte, eq, neq, between, in_range)
  - threshold (NUMERIC 18,6, nullable)
  - action (ENUM: pass, flag, reject, warning)
  - is_mandatory (BOOLEAN)
  - is_active (BOOLEAN)
  - priority (INTEGER, default 100)
  - failure_message, pass_message (TEXT, nullable)
  - industry (ENUM, nullable) — industry-specific rules
  - extra_config (JSONB, nullable)

TABLE: audit_logs
  - action (ENUM: various audit actions)
  - description (TEXT)
  - user_id (FK → users.id, nullable)
  - entity_type, entity_id
  - old_values, new_values (JSONB, nullable)
  - ip_address, user_agent, request_id

  PATCH  /users/{id}/status       — Change user status

11. PROCESSING PIPELINE (End-to-End)
================================================================================

The automated pipeline processes a loan application through these stages:

1. DOCUMENT UPLOAD
   - Company uploads annual report PDF (up to 100 MB)
   - Stored in uploads/ directory with SHA256 checksum
   - Document record created in DB with status "uploaded"

2. ANNUAL REPORT ANALYSIS (for annual_report type)
   - Analyzes PDF to detect Table of Contents (TOC)
   - If TOC found: parses TOC entries to find financial statement page numbers
   - If no TOC: keyword scan across all pages
   - Detects 3 section types: Balance Sheet, Profit & Loss, Cash Flow Statement
   - Distinguishes Standalone vs Consolidated (prefers Standalone for lending)
   - Detects monetary units (crore/lakh/million) and financial year
   - Creates sub-document records per detected section
   - MAX_SECTION_PAGES = 8 per financial statement

3. OCR EXTRACTION
   - For each section/document:
     - PyMuPDF extracts native text first
     - Falls back to Tesseract OCR if native text is insufficient
     - OpenCV preprocessing for scanned documents
   - parse_financials() extracts structured financial fields:
     - Total Revenue, Net Profit, Total Assets, Total Liabilities
     - Current Assets, Current Liabilities, Shareholders Equity
     - Operating Profit, EBITDA, Depreciation, Interest Expense
     - Cash from Operations/Investing/Financing
     - Inventory, Trade Receivables, Trade Payables
     - Long Term Debt, Short Term Debt, etc.
   - For annual reports: merges best-confidence fields from all sections

4. FINANCIAL RATIO CALCULATION
   - Computes 20+ ratios from extracted financial data:
     - Liquidity: Current Ratio, Quick Ratio, Cash Ratio
     - Profitability: Net Profit Margin, ROA, ROE, Operating Margin
     - Leverage: Debt-to-Equity, Debt-to-Assets, Interest Coverage
     - Efficiency: Asset Turnover, Inventory Turnover, Receivable Days
     - Coverage: DSCR, Times Interest Earned
   - Generates overall health assessment (healthy/warning/critical)

5. RULE ENGINE EVALUATION
   - Evaluates application against active rules
   - Rules are configurable (CRUD in admin)
   - Industry-specific rules supported
   - Each rule: metric_field + operator + threshold → pass/flag/reject/warning
   - Mandatory vs optional rules
   - Priority-based execution order

6. ML PREDICTION
   - XGBoost is the PRIMARY model (forced as default)
   - Also available: Logistic Regression, Random Forest
   - Dataset: company_bankruptcy_prediction.csv
   - SMOTE oversampling for class imbalance
   - Outputs: probability_of_default, risk_score (0-100), risk_level
   - SHAP values for explainability (per-feature contribution)
   - Auto-generates final decision: APPROVED/REJECTED/MANUAL_REVIEW

7. CREDIT REPORT GENERATION
   - PDF report generated using ReportLab
   - Contains: company info, financial summary, ratios, rule results,
     ML prediction, SHAP explanation, risk assessment, recommendation
   - Stored in reports/ directory
   - Versioned (v1, v2, etc.)

AUTOMATIC DECISION LOGIC:
  - risk_score < 35 → APPROVED
  - risk_score > 65 → REJECTED
  - 35 ≤ risk_score ≤ 65 → MANUAL_REVIEW

12. ML MODULE DETAILS
================================================================================

DATASET:
  - File: datasets/company_bankruptcy_prediction.csv
  - Configurable via DATASET_PATH in .env

MODELS:
  - XGBoost (PRIMARY — forced as default)
  - Random Forest
  - Logistic Regression

TRAINING (backend/ml/trainer.py):
  - Train/test split: 80/20 (configurable via TEST_SIZE)
  - Cross-validation: 5-fold (configurable via CV_FOLDS)
  - SMOTE oversampling for imbalanced classes
  - Feature scaling: StandardScaler
  - Random state: 42 (configurable)
  - Models saved to models/ directory with metadata.json

PREDICTION (backend/ml/predictor.py):
  - Loads trained model from models/ directory
  - Generates probability_of_default
  - Computes SHAP values for explainability
  - Generates risk_score (0-100 scale)
  - Determines risk_level: low (<30), medium (30-60), high (60-80), critical (>80)

FEATURES (backend/ml/features.py):
  - Feature engineering from extracted financial ratios
  - Feature configuration in config/feature_config.json

16. KEY ARCHITECTURAL PATTERNS
================================================================================

BACKEND ARCHITECTURE: Layered Architecture
  API Routes → Services → Repositories → Models
  - Routes: Thin controllers, request validation, response formatting
  - Services: Business logic, orchestration, transactions
  - Repositories: Data access, queries, CRUD operations
  - Models: ORM definitions, relationships, enums

FRONTEND ARCHITECTURE:
  Pages → API Client → Zustand Store
  - Pages: Full page components with local state
  - API Client: Axios-based modules per domain
  - Store: Zustand for auth state (minimal global state)
  - Forms: React Hook Form for complex forms

DATABASE:
  - UUID primary keys everywhere
  - Auto-managed created_at/updated_at timestamps (via SQLAlchemy Base mixin)
  - JSONB fields for flexible data (extracted_fields, ratios, shap_values)
  - Cascading deletes where appropriate
  - Indexes on frequently queried columns

ERROR HANDLING:
  - Custom exception classes (AuthenticationError, NotFoundError, ConflictError, etc.)
  - Global exception handler middleware
  - Structured error responses: { success: false, error: { code, message, status, detail } }
  - Frontend: extractError() utility for consistent error display

SECURITY:
  - JWT authentication with configurable expiry
  - Password hashing with bcrypt (via passlib)
  - Password strength validation (min 8 chars, uppercase, number)
  - CORS configuration (allowed origins in .env)
  - Rate limiting (60 req/min via slowapi)
  - File upload validation (size, type)
  - SQL injection prevention (SQLAlchemy ORM)
  - Request ID tracking for audit trail
  - Audit logging for sensitive operations
